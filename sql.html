Conceitos essenciais

Tabelas e relacionamentos

A chave primária identifica cada linha. Uma chave estrangeira aponta para uma chave de outra tabela. Modele uma relação N:N com uma tabela de associação que contenha as duas chaves.

Normalização

Na 1FN, mantenha valores atômicos e evite grupos repetidos. Na 2FN, cada atributo que não é chave deve depender da chave candidata inteira. Na 3FN, evite dependências transitivas entre atributos não chave.

DDL e CRUD

CREATE TABLE define estrutura e restrições. INSERT cria linhas, SELECT consulta, UPDATE altera e DELETE remove. Use WHERE em alterações específicas e verifique o filtro com SELECT antes da mudança.

Junções e agregações

INNER JOIN retorna pares correspondentes. LEFT JOIN mantém as linhas da esquerda mesmo sem correspondência. WHERE filtra linhas antes de agrupar. HAVING filtra grupos após GROUP BY. COUNT(coluna) ignora NULL.

NULL, índices e transações

Teste ausência de valor com IS NULL. Índices podem acelerar buscas ao custo de espaço e manutenção na escrita. Em uma transação, COMMIT confirma o conjunto de mudanças e ROLLBACK o desfaz enquanto estiver aberto.

Pedidos por cliente

SQL
CREATE TABLE clientes (
  id INTEGER PRIMARY KEY,
  nome VARCHAR(100) NOT NULL
);
CREATE TABLE pedidos (
  id INTEGER PRIMARY KEY,
  cliente_id INTEGER NOT NULL REFERENCES clientes(id)
);

INSERT INTO clientes VALUES (1, 'Ana'), (2, 'Bia');
INSERT INTO pedidos VALUES (10, 1), (11, 1);

-- Conta apenas pedidos existentes e mantém clientes sem pedidos.
SELECT c.nome, COUNT(p.id) AS total
FROM clientes AS c
LEFT JOIN pedidos AS p ON p.cliente_id = c.id
GROUP BY c.id, c.nome
ORDER BY total DESC, c.nome;

Resultado: Ana 2, Bia 0. Com COUNT(*), a linha sem correspondência também seria contada. A consulta usa sintaxe compatível com SQLite e PostgreSQL.

Exercícios de revisão

Tente resolver antes de abrir a resposta.

Como retornar apenas clientes com dois ou mais pedidos?

Resposta. Acrescente HAVING COUNT(p.id) >= 2 após GROUP BY e antes de ORDER BY.

Onde guardar o endereço do cliente para evitar repetição em cada pedido?

Resposta. Na tabela clientes, quando for o endereço cadastral atual. Um endereço de entrega histórico pode ser gravado no pedido para preservar o destino original.
