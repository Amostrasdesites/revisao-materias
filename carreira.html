Conceitos essenciais

Papéis e ciclo do software

Produto prioriza problemas, design investiga a experiência, engenharia implementa e opera, e qualidade ajuda a prevenir e detectar falhas. Requisitos, desenvolvimento, testes, entrega e manutenção se repetem conforme o produto evolui.

Git e colaboração

Um commit registra um conjunto de mudanças. Uma branch isola uma linha de trabalho. Um pull request reúne contexto, alterações e evidências para revisão. Prefira commits com um propósito claro.

Qualidade e testes

Teste unitário verifica uma unidade isolada. Teste de integração verifica componentes trabalhando juntos. Teste ponta a ponta percorre o fluxo do usuário. Cubra entradas válidas, inválidas e valores de fronteira.

Portfólio e entrevistas

Mostre problema, decisões, instruções de execução e testes no README. Para entrevistas, use situação, tarefa, ação e resultado. Explique sua contribuição e apresente evidências mensuráveis quando disponíveis.

Ética e rotina

Use dados fictícios em projetos públicos e mantenha credenciais fora do repositório. Divida tarefas em entregas pequenas, comunique bloqueios cedo e registre decisões que afetem a equipe.

Git em uma entrega

Terminal 
git switch -c melhoria-validacao
# Após editar e testar a alteração:
git add cadastro.js
git diff --staged
git commit -m "Valida e-mail no cadastro"

A branch isola a alteração. O diff mostra o conteúdo preparado para o commit. O comando pressupõe um repositório Git e o arquivo editado.

Exercícios de revisão

Tente resolver antes de abrir a resposta.

Que teste confirma a comunicação entre a API de cadastro e o banco?

Resposta. Um teste de integração, usando um banco de teste e verificando o registro persistido.

Como demonstrar uma entrega no portfólio?

Resposta. Documente o problema, suas decisões, os passos para executar, os testes e o resultado observado.
